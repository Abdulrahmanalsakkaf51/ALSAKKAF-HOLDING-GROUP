## Network Security

When disabled, the service does not load the source registry, initialize a transport, create a child process or IPC channel, read or write the cache, resolve DNS, or send HTTP. Health is `NEWS_DISABLED`. When enabled, only the exact governed source record and immutable HTTPS endpoint are supplied to an owned local child process whose target is a top-level importable standard-library function compatible with Windows spawn. The child derives the hostname and path only after complete registry validation and performs the entire DNS, connection, TLS, request, response-status, header, and bounded-body operation. No shell or externally constructed command is invoked, and retrieval has no query parameters, redirects, cookies, authentication, credentials, proxy surface, user URLs, browser-side publisher requests, or shared headers. The fixed user agent is `ALSAKKAF-TRL/2.0-r2.004 local-official-news-metadata` and contains no personal data. Connection and read inactivity timeouts remain fixed at 5 and 10 seconds inside the child. Windows process creation is a local platform operation outside the post-spawn 20-second publisher-retrieval deadline. The parent registers the exact record as `STARTING` before synchronous `Process.start()` and releases the global child-registry lock before making that platform call. Python's standard Windows multiprocessing API cannot safely preempt a blocked start. Shutdown can mark a `STARTING` record cancelled promptly, but completion waits for the platform call; if it returns with a child, the exact record transitions to `RUNNING` and immediately finalizes that child before shutdown can be reported. The fixed, non-configurable 20-second monotonic deadline begins immediately after successful start and covers child import and entry, DNS, connection, TLS, request, response status, headers, bounded body, and IPC completion. A parent-side retrieval-clock failure is `NEWS_SOURCE_INTERNAL_ERROR`, never HTTP, timeout, or provider change, and exposes no exception text. Continuous publisher trickle cannot extend that post-spawn deadline. The IPC frame is bounded consistently with the 1 MiB body limit. Every process record follows `STARTING`, `RUNNING`, `FINALIZING`, and `FINALIZED`. One record-owned finalizer exclusively captures exit status, requests terminate or kill, waits on the sentinel, performs exactly one join for a started child, closes each parent pipe endpoint once, closes the process handle once, and unregisters the exact record. A start failure performs no join, closes the unstarted process object and both pipe endpoints, and unregisters the record. Normal completion, timeout, crash, malformed or oversized IPC, internal clock failure, cancellation, and shutdown use that same idempotent finalizer; no normal-completion/shutdown race can join or close twice. The parent never returns while its successfully started source child remains alive. Each response is limited to 1 MiB and 200 entries. Compressed responses, invalid status, redirects, endpoint changes, and invalid content types fail closed. Refresh preparation briefly locks state to check enablement and throttle, selects one generation/owner token, marks `refreshing`, and captures immutable registry, trusted-cache, and configuration snapshots. A concurrent news read or refresh request immediately receives a deep-copied trusted snapshot with `refreshing=true`; it never waits for publisher I/O. The owner performs six bounded source operations, parsing, validation, candidate construction, pruning, and serialization without the state lock, then briefly reacquires it to verify ownership and accept or roll back the candidate in registry order. Atomic persistence also occurs without the state lock while `refreshing` remains true; readers can observe the accepted in-memory snapshot and current persistence state. A final owner-checked locked section records persistence success or failure and clears the correct owner. Coordinator-thread start failure clears the exact thread reference and owner, preserves the trusted snapshot, and permits a later throttling-eligible retry. Application shutdown obtains the actual service stored on the server, marks all source records cancelled, waits for their finalization and the coordinator, guarantees server closure in a nested final section, and prints the stopped message only after both complete. A blocked Windows start call can extend this shutdown because the lifecycle record is never abandoned. Unexpected failures become governed failure states without exception text, and owner-token finalization prevents a stale operation from clearing newer state. The localhost server nonblockingly admits at most 16 concurrent non-daemon request handlers and joins them on close. If all slots are occupied, an accepted overflow socket is immediately shut down and closed without parsing, response invention, active-handler registration, timer creation, queued handler creation, or semaphore release. Every admitted socket receives the fixed five-second inactivity timeout and its first fixed ten-second absolute request-line/header deadline before handler-thread scheduling. That same single deadline is claimed by the first request; each later keep-alive request receives one new independent deadline. A deadline cannot be extended by trickle input, is canceled and joined immediately after valid headers are parsed, and does not cover route processing. Expiry closes only that client and releases the handler slot; idle-client shutdown remains bounded by 6 seconds and absolute-header-deadline shutdown plus close by 11 seconds.

## Parser Security

Only Python's standard library is used. XML bytes are bounded before strict UTF-8 decoding. `DOCTYPE` and `ENTITY` declarations are rejected before `ElementTree` parsing. Documents are limited to 5,000 elements, depth 24, 200 entries, bounded attributes and element text, and 500-character retained titles. Only RSS/Atom title, official link, and publisher timestamp fields are retained. Namespace-local structure distinguishes RSS `item` from Atom `entry`. Atom publication time uses `published` whenever present, otherwise `updated`, otherwise null; a malformed present `published` fails closed instead of falling through, and XML child order cannot change the choice. RSS independently prefers `pubDate`, then `date`. Atom inspects every direct `link`, accepts only `rel="alternate"` or the absent default relation, and ranks `text/html` or `application/xhtml+xml` first, a missing media type second, and other alternate media types third, preserving document order within a rank. Self, enclosure, related, payment, and other relations are never article links. Existing URL governance is applied only after this deterministic selection. Before title text is flattened, governed tag tokens are compared case-insensitively and split on colon and dot boundaries. If any component is a blocked or void name, the tree walk and shared title/event-name canonicalizer discard the complete element contents while preserving safe surrounding and tail text; this covers namespace-like and dotted forms such as `x:script`, `svg:style`, and `script.foo`, including encoded and multiply encoded forms. The shared canonicalizer applies at most eight bounded decode/parse passes, normalizes safe whitespace, rejects mismatched, unclosed, malformed, or residual angle-bracket markup with a blocked-tag stem, and rejects Unicode control/format characters and ambiguous non-stabilizing input. Ordinary safe mathematical text containing `<` or `>` is retained. The result is deterministic, idempotent, Arabic-preserving, and limited to 500 characters. Fresh parsing and untrusted cache validation require this identical invariant; a self-consistent fingerprint cannot authorize noncanonical markup. Content, description, image, tracking, executable markup, article-body fields, and arbitrary attributes are ignored.

JSON uses strict UTF-8, duplicate-key rejection, nonfinite-number rejection, depth 16, collection limit 2,000, entry limit 200, string limit 4,096, two narrow BEA structures, an explicit field allowlist, strict timestamp parsing, and rejection of booleans for governed optional values. BEA date-only input requires an exact full `YYYY-MM-DD` grammar match before calendar validation; compact, week-date, whitespace, and suffixed forms fail as `NEWS_SOURCE_SCHEMA_INVALID`, while separately valid RFC3339 timestamps use the strict timestamp parser. Decoder or traversal `RecursionError` is converted to a fixed governed parse error without retaining exception text or source content. There is no `eval`, `exec`, pickle, YAML, dynamic import, or object hook supplied by source data.

## Data Schemas

`TRL-OFFICIAL-NEWS-ITEM-1.3` contains only schema version, stable news ID, source ID, publisher, safe title, governed official source URL, explicit URL availability/reason fields, identity basis and ambiguity reason, published and retrieved UTC timestamps, region, currency tags, category, revision number, quality, retention status, limitations, and API-projected operational freshness metadata. It has no body, image, summary, sentiment, impact, strategy association, or relevance score.

`TRL-OFFICIAL-ECONOMIC-EVENT-1.3` separates a governed series from an occurrence. `event_series_id` hashes source identity, sanitized event name, and either the complete governed canonical URL or explicit endpoint-fallback basis. `event_id` additionally hashes the normalized scheduled timestamp marker and `DATE_ONLY` or `TIMESTAMP` precision. The schema records both identity bases and explicitly states that, because no source occurrence ID is supplied, a changed scheduled date is a new occurrence and reschedule continuity cannot be reliably inferred. Retrieval time, cache state, ordering, and process state affect neither ID. Optional actual, forecast, previous, and importance values remain source-only and null with `SOURCE_NOT_PROVIDED` when absent. A BEA date-only value is a midnight UTC date marker, not an official release time.

## Deduplication, Revisions, and Ordering

News with a governed unique item URL retains SHA-256 identity over source ID and the complete canonical URL, including an accepted query in its original order. When the URL is unavailable, identity instead uses source ID, explicit `SOURCE_ENDPOINT_FALLBACK` state, canonical title, and the source-supplied publication timestamp or `SOURCE_NOT_PROVIDED`; retrieval time, ordering, cache state, random data, and process state are excluded. Nonzero fractional publication seconds survive UTC normalization, unnecessary trailing zeros are removed, equivalent instants normalize identically, and fractionally distinct instants therefore produce distinct fallback identities. Same-title fallback observations with no publisher timestamp are explicitly marked ambiguous. Two records in one source batch with the same endpoint-fallback identity reject that entire new batch as `NEWS_SOURCE_SCHEMA_INVALID`; trusted records for that source remain stale, independent sources continue, and the invalid batch is never written or treated as revisions. Economic events first derive a source-separated series identity, then derive occurrence identity from series, schedule marker, and precision. Different scheduled dates cannot merge as revisions. Same-series content changes that do not change schedule may increment revision. Results order events by scheduled timestamp, series ID, and occurrence ID, independent of completion order.

## Local Cache

Production storage is `%LOCALAPPDATA%\ALSAKKAF_TRL\official_news\cache-v1.json`. No arbitrary cache path is accepted by CLI. The strict schema is `TRL-OFFICIAL-NEWS-CACHE-1.0`; it retains at most 1,000 combined records, 5 MiB serialized, and 30 days. Every cache document and record is untrusted. Validation requires exact built-in JSON types, exact wrapper and current news/event field sets, compatible versions, canonical UTC timestamps, bounded strings and collections, finite permitted values, complete null/reason pairings, source metadata equal to a revalidated immutable registry record, and no serialized operational-freshness fields. It reapplies governed query/link and fallback policies, recomputes news ID or both event series/occurrence IDs, then recomputes the content fingerprint. A constructed production-storage object is retained before cache load. Malformed, nonfinite, incompatible, or schema-invalid contents are rejected completely into a new empty trusted in-memory document, while the same storage remains available for an atomic repair after the next complete validated refresh. Each write uses `tempfile.mkstemp` to atomically create a unique same-directory sibling, writes canonical bytes, flushes and closes it, then uses `os.replace`. Legacy fixed or crash-left unique temporary siblings cannot block a new attempt and are never opened, followed, overwritten, or deleted. A controlled failure closes its descriptor and removes only the exact new sibling created by that attempt. A successful repair returns persistence to `NEWS_VALID`, and a later service instance loads the replacement normally; a failed repair reports `NEWS_CACHE_WRITE_FAILED`. Storage-construction failure is also controlled without exposing paths or exceptions. Disabled mode constructs, reads, and writes no storage. Refresh application is transactional and two-phase around unlocked work: the validated pre-refresh cache remains live while each source batch is completely record-validated; a failed batch is rejected as a unit and retains its prior records. Successful batches merge into a deep-copied candidate in registry order without the state lock. Pruning, full cache validation, bounds, and canonical serialization must all pass before the short owner-checked application section changes the live cache reference. Final-candidate failure retains the trusted snapshot, never substitutes empty data, never writes the candidate, and never reports `NEWS_VALID`. Persistence occurs only after accepted in-memory application, without the state lock. Persistence failure remains independent, preserves the accepted candidate, records the restart-loss warning, and permits a later successful refresh to recover.
