## Metadata, Schemas, and Redistribution Controls

RSS/Atom uses `TRL-OFFICIAL-NEWS-ITEM-1.3`; accepted query text remains part of its governed URL identity. Atom structure is handled separately: `published` takes precedence over `updated` regardless of child order, and only an explicit or default `alternate` direct link is eligible. HTML/XHTML alternates rank before missing-type and other alternate media types; same-rank document order is stable. Self, enclosure, related, payment, and other relations are excluded. RSS independently prefers `pubDate`, then `date`. BEA events use `TRL-OFFICIAL-ECONOMIC-EVENT-1.3`: series identity binds source, safe name, and governed URL or fallback basis, while occurrence identity additionally binds schedule marker and precision. A source without an occurrence ID cannot support reliable reschedule continuity, so a changed date is explicitly a new occurrence. Retrieval time, ordering, cache state, and operational freshness do not affect IDs. Before flattening XML title text, namespace-aware tree sanitation removes blocked and void subtrees while retaining safe tails. The tree sanitizer and shared bounded canonicalizer compare tag names case-insensitively and split governed tokens on colon and dot boundaries; any blocked component discards the complete element and contents, including namespace-like and dotted forms. At most eight stabilization passes decode encoded and multiply encoded markup identically, preserve safe surrounding text and Arabic, normalize whitespace, reject malformed or residual angle-bracket markup bearing a blocked-tag stem, reject ambiguous non-stabilizing input plus Unicode control/format characters, and produce an idempotent result. Ordinary safe mathematical `<` and `>` text is not rejected solely for those characters. Fresh source records and untrusted cached titles/event names must satisfy the same exact canonical form. Descriptions, bodies, scripts, styles, images, tracking, embedded content, attributes, and forms are discarded.

BEA schedule retention adds event name, schedule UTC marker and precision, optional publication UTC, optional source-supplied actual/forecast/previous/importance, explicit missing reasons, and governed link availability. Missing values remain null; no forecast, importance, direction, causal effect, or strategy relevance is invented. A date-only value is accepted only after an exact `YYYY-MM-DD` grammar match and calendar validation, then identified as `DATE_ONLY`, not an official release time. Canonical UTC timestamps preserve nonzero microsecond precision, remove unnecessary trailing fractional zeros, and normalize equivalent instants identically.

`REDISTRIBUTION_NOT_AUTHORIZED` means the design does not claim or exercise a right to redistribute publisher full text. `TITLE_LINK_METADATA_ONLY` and `FULL_TEXT_NOT_RETAINED` are enforced by parser fields, cache schema, tests, and dashboard construction. External links are navigation to validated official publisher URLs and use safe text nodes, `target="_blank"`, and `rel="noopener noreferrer"`.

## Retrieval, Cache, Health, and API Governance

Default startup is network-silent and reports `NEWS_DISABLED`: no registry initialization, child process, IPC channel, DNS, HTTP, or cache write. Explicit enablement runs each complete governed source operation in an owned spawn-compatible child whose top-level target receives only the exact source record and immutable endpoint. It invokes no shell and permits no redirect, proxy, cookie, authentication, credential, user URL, browser fetch, or shared key. Windows process creation is a local platform operation outside the post-spawn publisher-retrieval deadline. The exact lifecycle record is registered as `STARTING` before synchronous `Process.start()` runs, without holding the global record lock. Python's standard multiprocessing API cannot safely preempt a blocked Windows start call. Shutdown can mark the starting record cancelled immediately, then waits; if the call returns with a child, that exact child is terminated and finalized before shutdown completion is reported. Immediately after successful start, the parent begins a fixed non-configurable 20-second monotonic deadline covering child import and entry, DNS, connection, TLS, request, response status, headers, bounded body, and IPC completion. A failure of that parent-side clock is the sanitized `NEWS_SOURCE_INTERNAL_ERROR`, not an HTTP, timeout, or provider-change result, and uses the same exactly-once finalizer. Fixed five-second connection and ten-second inactivity controls remain inside the child, and continuous publisher trickle cannot extend the post-spawn deadline. IPC is bounded by the one-MiB response policy. A record-owned `STARTING`, `RUNNING`, `FINALIZING`, `FINALIZED` state machine gives one finalizer exclusive ownership of exit status, termination or kill, one join, both parent pipe endpoints, one process close, and record removal. No join occurs before successful start or outside the finalizer. Repeated shutdown and finalization are harmless, and no owned source child remains alive on return. Crashes, malformed IPC, serialization failures, abnormal exits, and oversized results fail closed. Refresh preparation briefly holds the state lock to select one generation/owner token and capture immutable registry, trusted-cache, and configuration snapshots. Six source operations, parsing, complete source-batch validation, merge, pruning, candidate validation, and serialization run without that lock. Concurrent news reads immediately return deep-copied trusted data with `refreshing=true`, and health remains responsive; only one refresh can own the lifecycle. A short owner-checked application section accepts or rolls back the candidate transactionally in registry order. Atomic persistence then runs unlocked while the accepted in-memory candidate remains readable and `refreshing` stays true. A guaranteed owner-checked final section records persistence status and clears the correct owner; a failed write retains the valid memory candidate. One invalid row or duplicate endpoint-fallback identity rejects that source's new batch, preserves trusted records as stale, performs no invalid-candidate write, and does not block valid sources. The localhost server retains its nonblocking 16-handler bound, five-second per-read inactivity timeout, and joined non-daemon shutdown. An accepted overflow socket is immediately shut down and closed without parsing, response invention, handler/timer registration, queuing, or unmatched semaphore release. Each admitted connection begins its first fixed ten-second absolute request-line/header deadline before handler-thread scheduling; each keep-alive request receives one later independent deadline. Trickle input cannot extend it, and the timer is canceled and joined before route processing. The shutdown-plus-close bound remains 11 seconds. Application shutdown invokes the actual server-owned news service, cancels and finalizes its source records, joins its refresh coordinator, closes the server in a guaranteed nested final section, and prints the stopped message only afterward. A blocked platform start call can extend that completion because the application will not abandon its lifecycle record.

The local cache is `%LOCALAPPDATA%\ALSAKKAF_TRL\official_news\cache-v1.json`, schema `TRL-OFFICIAL-NEWS-CACHE-1.0`, with 1,000 combined records, 5 MiB, 30 days, deterministic pruning, and atomic replacement. It contains no raw body, image, cookie, secret, credential, MT5, account, or cloud data. Cache content is untrusted: exact current fields/types are required; operational freshness is forbidden; source attribution, complete governed query URLs, fallback state, news ID, event series ID, occurrence ID, and fingerprints are recomputed. A malformed stored record rejects the whole cache. The already constructed production-storage object is nevertheless retained, so the next completely validated refresh can atomically replace the rejected file without manual deletion. Every attempt atomically creates its own unique same-directory temporary file, closes it before replacement, and removes only that exact file on failure. Stale fixed or unique siblings remain untouched and cannot block recovery. Successful repair makes the replacement loadable on restart; failed repair is independently `NEWS_CACHE_WRITE_FAILED`. Storage construction failure is controlled, while disabled mode performs no storage construction, read, or write. A malformed new source batch instead fails that source transactionally without erasing the already trusted cache.

Health codes cover disabled, no data, refreshing, valid, partial, all failed, timeout, HTTP, sanitized internal lifecycle/control failure, redirect, size, content type, UTF-8, unsafe XML, parse, schema, stale, local throttle, cache invalid/write failure, and provider change. `NEWS_SOURCE_INTERNAL_ERROR` is never used for a genuine HTTP or publisher failure and never exposes exception details. Adding it advances only the health API from `TRL-OFFICIAL-NEWS-HEALTH-1.1` to `TRL-OFFICIAL-NEWS-HEALTH-1.2`; item, event, collection, cache, registry, endpoint, host, and compiled source identities remain unchanged. Source retrieval, per-source health, cache freshness, and cache persistence remain independent. All four news APIs expose stable cache-persistence status/reason fields; a failed write reports `NEWS_CACHE_WRITE_FAILED` without replacing `NEWS_PARTIAL` or mislabeling a source, preserves in-memory records, and shows a fixed memory-only/restart-loss warning until a later successful write clears it. The cumulative network-request count advances exactly once per real connector attempt, including controlled failures, and never for disabled, cache-only, repeated snapshot, or locally throttled access. The localhost `GET`/`HEAD` routes are `/api/news-health`, `/api/news-sources`, `/api/news-items`, and `/api/economic-events`; no mutation or refresh-bypass route exists. Dashboard states are disabled, loading, empty, valid, partial, stale, persistence-warning, and error, with attribution, UTC/local qualification, null labels, accessible tables, visible focus, mobile layout, and reduced motion.
